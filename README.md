# شركة وادي بناء للنقل الدولي — دليل التشغيل

## ملفات التطبيق

- `index.html`: نقطة الدخول للتطبيق الثابت أحادي الصفحة.
- `assets/css/app.css`: أنماط الواجهة وتنسيقات الطباعة.
- `assets/js/app.js`: ملف JavaScript مشترك؛ التطبيق الرئيسي في `index.html` يستخدم Firebase Authentication وRealtime Database.
- `assets/images/wadi-bina-logo.jpeg`: شعار وادي بناء المستخدم في الواجهة والتقارير.
- تستخدم الصفحة الملفات ذات الأسماء الأساسية أعلاه؛ الملفات التي تحمل `(2)` نسخ مكررة غير مرتبطة.
- `app-compat.js`: ملف توافق قديم مستقل؛ لا تضفه إلى الصفحة الرئيسية، إذ يكرر أسماء دوال موجودة في التطبيق.
- `wadi_bana_unified.php` و`api.php`: بدائل PHP تتصل بـFirebase عبر REST، وتحتاج استضافة PHP مع امتداد cURL.
- لوحة إدارة المستخدمين تدعم الأدوار الإدارية الموسعة، تفعيل/إيقاف الحسابات، وحماية حسابات المالك، مع تسجيل عمليات الإدارة في `systemAuditLogs` داخل Firebase.
- يستخدم إعداد Firebase الحالي خدمات Authentication وRealtime Database فقط، ويمكن تشغيلهما على خطة Spark المجانية ضمن حصص الاستخدام. لا تُنشر Cloud Functions مع `backend/firebase.json`.
- في خطة Spark، يدير المسؤول ملفات المستخدمين والصلاحيات من الواجهة ويستطيع إيقاف الحسابات. تغيير اسم الدخول أو كلمة مرور مستخدم آخر أو حذف حساب Authentication يتم من Firebase Console. المستخدم المسجل دخوله يستطيع تغيير كلمة مروره بنفسه.
- تسجيل الدخول باسم مستخدم يستخدم عنوان Authentication اصطناعياً، لذلك لا يعمل رابط استعادة البريد الإلكتروني. استعادة كلمة المرور تتم يدوياً من Firebase Console؛ لمطابقة رقم الهاتف آلياً أو تغيير بيانات Authentication للآخرين يلزم خادم موثوق، مثل Cloud Functions على خطة Blaze.
- يسجل المستخدم دخوله عبر Firebase Authentication (Email/Password). تحوّل الواجهة اسم المستخدم إلى عنوان مصادقة داخلي مشتق من `projectId`؛ كلمة المرور تُدار في Authentication ولا تُخزّن في Realtime Database. تحفظ `users/{UID}` ملف العرض والصلاحيات فقط، مثل:

  ```json
  {
    "username": "example-user",
    "fullName": "اسم المستخدم",
    "role": "employee",
    "branchId": "ajman",
    "active": true,
    "hidden": false,
    "authEnabled": true,
    "phone": "0500000000"
  }
  ```

  أنشئ الحسابات من لوحة إدارة المستخدمين أثناء الدخول بحساب الإدارة. يتطلب كل حساب Firebase Authentication وملفاً مقابلاً في `users/{UID}`؛ التطبيق لا ينشئ حسابات افتراضية عند أول تشغيل. لا تدخل كلمات مرور حقيقية في ملفات المشروع أو الأكواد. الحساب `mahmoud.abdulkarim` يبقى مخفياً عبر `hidden: true` وتُحصر به إدارة ملفات المستخدمين في التطبيق.

  يطلب نموذج إنشاء المستخدم رقم هاتف لاستخدامه كبيان ملف شخصي. على خطة Spark لا يُستخدم الرقم للتحقق الآلي أو تغيير كلمة المرور؛ مطابقة الرقم وحدها لا تثبت ملكية الهاتف. تُجرى استعادة كلمة المرور وتغييرات اسم الدخول أو كلمة مرور مستخدم آخر وحذف حساب Authentication يدوياً من Firebase Console.
- قواعد المسارات الحالية موجودة في `firebase.database.rules.json`. عندما يُستبدل Firebase Authentication، يجب مراجعة القواعد بدقة لأن القراءة والكتابة العامة تُعد ثغرة أمنية ولا توفر عزل الصلاحيات على الخادم.
- مخطط `systemUnifiedData` الحالي موحد على كل الفروع؛ لذلك صلاحيات الفرع في الواجهة ليست حاجزاً أمنياً. يلزم تقسيم البيانات إلى مسارات مستقلة حسب الفرع قبل فرض عزل فرعي موثوق.

## التشغيل

1. من مجلد المشروع شغّل `python -m http.server 8000`، ثم افتح `http://localhost:8000/index.html`؛ لا تفتح الصفحة من `file://` لأن المتصفح قد يمنع وحدات JavaScript واتصال Firebase.
2. تأكد من تحميل CDN resources (Tailwind, Chart.js, html2canvas, jsPDF, PDF.js, XLSX, JsBarcode) ومن إعداد Firebase Realtime Database.
3. تبقى بدائل PHP منفصلة؛ شغّلها باستضافة PHP مع cURL، ولا تنقل إعداداتها أو ملفاتها إلى التطبيق الثابت.
4. اختبر الدخول، حفظ البيانات وإعادة تحميلها، انقطاع/عودة الشبكة، الطباعة والتصدير، واستعادة نسخة احتياطية قبل استخدام بيانات فعلية.

تحتوي الصفحة على تحويل مشروط من `wadibana.system.github.io` إلى `https://wadi-bana.github.io/system/` دون تحويل زوار العنوان الجديد. لكي يعمل العنوان القديم، يجب أن يوجَّه من إعدادات النطاق أو GitHub Pages إلى هذه الصفحة؛ الكود وحده لا ينشئ سجل DNS أو يربط نطاقاً غير متاح.

## تنبيه أمني مهم

إعداد Firebase للويب (بما فيه `apiKey`) يُحمّل في المتصفح، لذلك لا يُعد مفتاح API سراً ولا بديلاً عن المصادقة وقواعد قاعدة البيانات. يجب استخدام مفتاح Web API صالح للمشروع، وتفعيل Email/Password، ونشر قواعد Realtime Database المناسبة. لا تستخدم قواعد قراءة/كتابة عامة، ولا تضع Database Secret أو Service Account في JavaScript أو المستودع.

> هذا الملف المساعد يكمل دوال الطباعة وأسماء التصدير فقط، ولا يحل محل تهيئة Firebase أو تأمين النظام.
